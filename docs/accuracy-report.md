# 生成 AI 判定の精度実測レポート（2026-08-20）

このレポートは、a11y-shiken の **生成 AI（Claude）判定そのもの**（[SKILL.md](../skills/a11y-shiken/SKILL.md) ステップ5）が
どれくらい当たるのかを、正解データつきの検査対象で **盲検**（判定者に正解を伏せた条件）で実測した記録です。

axe-core / Visual / Interactive の機械検査の精度は対象外です。機械検査は決定的で、
検出内容は [examples/site/ground-truth.md](../examples/site/ground-truth.md) に実測済みの結果があります。

**先に結論を書きます。**

| 指標 | 実測値 |
|------|--------|
| **間違った合格**（正解が違反の項目に AI が pass / not-applicable を出した数） | **0 件**（生の判定・統合後とも、3 セッション全て） |
| **間違った不合格**（正解が違反としていない項目に AI が fail を出した数） | **0 件** |
| **AI が判定を試みた範囲** | 55 項目中 **15 〜 16 項目**（4 ページ 220 セル中 60 〜 64 セル = 27 〜 29%） |
| **検出**（正解の違反 21 件のうち） | AI が判定を試みた **8 件は 3 セッションとも全て fail**。残り **13 件は AI が判定を試みなかった** |
| 統合後（機械検査 + AI） | **14 件 / 21 が「修正あり」**。機械検査のみだと 9 件なので、AI が 5 件を上乗せ |
| precision（AI の「合格」判定の正しさ） | **1.000**（3 セッションとも） |
| 未確認率（判定を試みた中で warning） | **1.6% 〜 15.0%** |
| **独立 3 セッション間の一致率** | 全体 **79.7%**、3 体とも判定した項目に限ると **85.0%**、**正解の違反にあたるセルは 100%** |
| 証拠品質（evidence の幻覚） | **0 件 / 173 判定** |

**要点は 2 つです。**

1. **危険側には倒れませんでした。** 間違った合格 0 件、間違った不合格 0 件、正解の違反にあたるセルは 3 体が完全に一致。
2. **しかし守備範囲は狭いです。** 判定を試みたのは 55 項目のうち 15 〜 16 項目だけで、正解の違反 21 件のうち 13 件は
   そもそも判定の対象になりませんでした。**「間違えない」のは「判定できることしか判定しない」ことの裏返し**です。

数字を読むうえでの条件は [測定の限界](#測定の限界)にまとめています。

## 測定の経緯

**このレポートの数字は 2 回目の測定です。1 回目は無効にしました。**

1 回目は、判定を行った AI が同一セッション内で `ground-truth.md`（どこに何を仕込んだかの一覧）を先に読んでいました。
正解を知ったうえでの判定は精度測定として成立しません。1 回目では検出 15 / 21 という値が出ましたが、
これは正解を知っていたから到達できた数字であり、採用しませんでした。

そこで検査対象を中立名（`alpha` / `beta`）にリネームし、対応関係を伏せたうえで、
**会話文脈を持たない独立した判定エージェント 3 体**に判定させ直したものが本レポートの数字です。

参考として、1 回目（汚染あり）と 2 回目（盲検）の差は次のとおりです。

| | 1 回目（正解を読んでいた・無効） | 2 回目（盲検・本レポート） |
|---|---|---|
| AI が判定を試みた範囲 | 55 / 55 項目 | 15 〜 16 / 55 項目 |
| 検出（生の AI 判定） | 15 / 21 | 8 / 21（試みた 8 件は全て検出） |
| 統合後の「修正あり」 | 19 / 21 | 14 / 21 |
| 間違った合格 | 0 | 0 |

**正解を知っていた判定者は「探しに行った」ぶん多く見つけていた**、というのが差の中身です。
間違った合格が 0 件である点だけは、両方の条件で共通していました。

## 1. 何を測ったか

a11y-shiken の判定は 4 つの経路の合成です（詳細は [how-it-works.md](how-it-works.md)）。

1. axe-core（機械・決定的）
2. Visual テスト（Playwright・決定的）
3. Interactive テスト（Playwright・決定的）
4. **生成 AI（Claude）判定** ← 今回の測定対象
5. 統合スクリプト `generate-checklist-xlsx.ts`（証拠必須ガード・遷移制限を適用）

測ったのは 4 と、4 が 5 を通ったあとの結果です。

自前の検証用ダミーサイト [examples/site](../examples/site/) の 4 ページ。
盲検のため、判定者には `ok` / `ng` ではなく `alpha` / `beta` の名前で提示しました。

| `alpha-contact` | `ok/contact.html` | 仕込んだ違反なし |
| `beta-index` | `ng/index.html` | 10 達成基準に違反を仕込み済み |
| `beta-contact` | `ng/contact.html` | 11 達成基準に違反を仕込み済み |

正解データは [ground-truth.md](../examples/site/ground-truth.md) の違反設計表です。
同表のうち `facility.html` の 4 件（NG-12 〜 NG-15）は対象外としました（測定対象を 4 ページに固定したため）。

ページごとの正解（達成基準 → ground truth の ID）:

## 2. 盲検プロトコル

### 盲検の設計

判定者が正解を知りえない条件を作るため、次の対策を取りました。

- 検査対象を `ok` / `ng` から **`alpha` / `beta` の中立名にリネーム**して `localhost:8377` で配信し、
  **どちらが適合版かは判定者に伏せた**
- 判定者は**会話文脈を持たない独立したエージェント 3 体**。互いの判定結果も、前の回の集計も見ていない
- 判定者に渡したのは次の 3 つだけ:
  1. SKILL.md ステップ5 の抜粋（正解情報を含まない）
  2. `a11y-tree.txt`
  3. `localhost:8377` 経由の HTML
- **リポジトリへのアクセスを禁止**（`ground-truth.md` に到達できない）
- SKILL.md ステップ5 に列挙されていない属性・観点を使わないことを明示
  （1 回目の測定で入力範囲がスキルの定義を超えていた問題への対策）
- **判定順序は 3 体で変えた**（順序効果の緩和）

### 判定対象の定義

**判定対象は判定者自身が選びました。**

1 回目の測定では分母を固定するため 55 項目すべてに判定を出させましたが、
盲検では SKILL.md ステップ5 の指示どおりに動かすことを優先し、
**「ツリー / HTML から判定できる項目」を判定者に選ばせています**。

結果として各判定者が判定を出したのは 1 ページあたり 15 〜 16 項目でした。
このため precision と未確認率の分母は **判定者が実際に判定した件数**であり、55 ではありません。
判定を出さなかった項目は AI 判定の対象外として、機械検査の結果がそのまま統合結果になります。

### 手順

1. **機械検査を各ページ 1 回**（決定的なので 1 回）
   - `a11y-test.ts`（axe-core）/ `a11y-visual-test.ts` / `a11y-interactive-test.ts` / `a11y-tree.ts`
   - 機械検査の結果 JSON は AI 判定の入力に **含めていません**（axe の答えを見てから判定すると測定にならないため）
2. **独立した判定エージェント 3 体が、それぞれ 1 回ずつ 4 ページを判定**
3. **各セッションについて `generate-checklist-xlsx.ts` で統合**し、`merged-result.json` を得る
4. **ground-truth.md と突き合わせて集計**

比較の基準線として、`claude-overrides.json` を空（`{"overrides":[]}`）にした「AI 判定なし」の統合結果も作成しました。

### 再現手順

```bash
# 1. 中立名で検査対象を配信（ok→alpha, ng→beta にコピーしてリネーム）
python3 -m http.server 8377 --directory <中立名にリネームした検査対象>

# 2. 機械検査（ページごとに実行。4 ページぶん繰り返す）
cd skills/a11y-shiken
bun scripts/a11y-test.ts             http://localhost:8377/beta/index.html > <dir>/axe-result.json
bun scripts/a11y-visual-test.ts      http://localhost:8377/beta/index.html > <dir>/visual-result.json
bun scripts/a11y-interactive-test.ts http://localhost:8377/beta/index.html --screenshot-dir <dir>/screenshots > <dir>/interactive-result.json
bun scripts/a11y-tree.ts             http://localhost:8377/beta/index.html --output <dir>/a11y-tree.txt

# 3. 正解を知らない独立エージェントに、SKILL.md ステップ5 の抜粋 + a11y-tree.txt + localhost の HTML
#    だけを渡して claude-overrides.json を書かせる（リポジトリへのアクセスは禁止）

# 4. マニフェストを書いて統合
bun scripts/generate-checklist-xlsx.ts --manifest <dir>/manifest.json --output <dir>/checklist.xlsx
```

集計の元データ（各セッションの `claude-overrides.json` / `merged-result.json`）はリポジトリに含めていません。
上の手順で再生成できます。集計結果は本レポートの表としてすべて転記しています。

## 4. 結果

### 4-1. 間違った合格（最重要）

**正解が違反とする 21 項目に対し、AI が pass / not-applicable を出した数。**

| | 生の `claude-overrides.json` | 統合後 `merged-result.json` |
|---|---|---|
| セッション1 | 0 | 0 |
| セッション2 | 0 | 0 |
| セッション3 | 0 | 0 |

**正解を知らない条件でも 0 件でした。**

ただし内訳を正確に見てください。21 件のうち **AI が判定を試みたのは 8 件**で、その 8 件は 3 セッションとも fail でした。
残り 13 件は判定自体を出しておらず、**「合格にしなかった」のではなく「判定しなかった」**状態です。

判定を試みなかった 13 件:

- beta-index: 1.1.1（NG-07 代替テキストが「画像」）/ 1.4.3 / 2.4.7 / 2.5.8
- beta-contact: 1.3.5 / 1.4.1 / 1.4.4 / 1.4.11 / 2.4.2（NG-16 タイトルが「ページ」）/ 2.4.7 / 2.5.3 / 3.2.3 / 3.3.2

このうち 1.4.3 / 1.4.4 / 1.4.11 / 2.4.7 / 2.5.3 は機械検査が「不適合」にしています。
一方 **1.1.1 と 2.4.2 は、機械検査でも AI でも捕まらず「未確認」で終わりました**。
どちらも「alt や title は存在するが内容を説明していない」という、まさに生成 AI に期待される種類の欠陥です。

### 4-2. ガードが実際に止めた件数

| ガード | 実装 | 今回の作動件数 |
|--------|------|----------------|
| 証拠必須ガード（`evidence` 空の pass / fail / not-applicable を warning へ降格） | `sanitizeClaudeOverrides()` | **0 件**（3 セッション合計 173 件の pass / fail / not-applicable すべてに evidence があった） |
| 遷移制限（証拠のない「適合」への上書きを却下） | `applyOverrideStatus()` | **0 件**（AI の「適合」判定はすべて証拠つきだった） |
| 判定矛盾フラグ `conflict: true` | 同上 | **0 件** |

**ガードは「今回も何も止めなかった」というのが実測結果です。** 本測定は **ガードの効果を実証していません**。

なお遷移制限の却下条件は「不適合 → 適合」に限りません。`applyOverrideStatus()` は**証拠のない「適合」への上書きをすべて却下**し、
証拠のある「不適合 → 適合」は却下せず `conflict: true` を立てて通します（却下条件と矛盾フラグの条件は別物です）。
さらに `sanitizeClaudeOverrides()` は `loadClaudeOverrides()` の中で読み込み時に適用されるため、
**AI の判定が `applyOverrideStatus()` に届く時点で証拠なしのものは残っていません**。
つまり却下の分岐は AI 経路では原理的に発生せず、Visual / Interactive の pass 提案でしか起こりえません。

また証拠必須ガードは `evidence` が**空文字でないこと**しか検査しません。
存在しない要素を引用した「幻覚した証拠」はこのガードを素通りします（今回の実測では幻覚 0 件 → [4-6](#4-6-証拠品質)）。

### 4-3. precision（AI が「合格」と言った判定の正しさ）

分母は AI が pass または not-applicable を出した判定の総数、分子はそのうち正解データが違反としていないものです。

| | pass | not-applicable | 合計（分母） | 間違った合格 | precision |
|---|---|---|---|---|---|
| セッション1 | 17 | 33 | 50 | 0 | **1.000** |
| セッション2 | 14 | 28 | 42 | 0 | **1.000** |
| セッション3 | 17 | 37 | 54 | 0 | **1.000** |

**この 1.000 は「仕込んだ違反を合格にしなかった」という意味であって、「alpha 版の 55 項目すべてが WCAG に適合していると確認できた」という意味ではありません。**
ground-truth.md が保証しているのは「仕込んだ違反の不在」であって、ok 版の全項目適合ではありません。

### 4-4. 検出（正解の違反を fail にできたか）

| ページ | 正解の違反 | AI が判定を試みた | うち fail | うち warning | うち pass（事故） | AI が判定しなかった |
|--------|-----------|------------------|----------|-------------|------------------|--------------------|
| beta-index | 10 | 6 | **6** | 0 | 0 | 4 |
| beta-contact | 11 | 2 | **2** | 0 | 0 | 9 |
| **合計** | **21** | **8** | **8** | **0** | **0** | **13** |

**判定を試みた 8 件は、3 セッションすべてで fail。取りこぼしも、危険側への誤りもゼロです。**
一方で、正解の違反の **62%（13 / 21）は判定の対象にすらなりませんでした。**

実際のアクセシビリティツリー / HTML と一致するかを照合しました。

| 種類 | 検証方法 | 件数 | 結果 |
|------|---------|------|------|
| 肯定的引用（「この要素・属性が存在する」） | 引用文字列がツリー / HTML に実在するか機械照合 | 73 判定 | **実在 73 / 実在しない 0** |
| 否定的主張（「この要素が存在しない」） | 主張された不在が実際に成り立つかをページから算出した事実表と照合 | 132 判定 | **主張どおり 132 / 誤り 0** |
| 定性的主張（読み上げ順など） | 目視レビュー | 4 判定 | **すべて確認、誤りなし** |

（1 つの判定が肯定的引用と否定的主張の両方を含む場合があるため、上 2 行は重複を含みます）

**存在しない要素・属性を引用した「幻覚した証拠」は 0 件でした。**

なお機械照合では 20 件が逐語一致しませんでしたが、**全件を手作業で確認した結果、すべて実在する要素の省略表記でした**。

- `<main id="main">` — 実体は `<main id="main" class="content">`
- `<svg aria-hidden="true">` / `<svg aria-hidden="true" ...>` — 実体は `<svg aria-hidden="true" focusable="false" viewBox="0 0 24 24">`
- `<input type="tel" id="tel">` — 実体は `<input type="tel" id="tel" name="tel" autocomplete="tel">`
- `label for="..."` — `...` は省略記号で、実体は `<label for="name">` 等

**要素そのものは全件実在します**が、逐語引用ではなく要約された引用が混ざる点は品質上の注意点です（→ [5 章](#5-発見事項)）。

### 4-7. 独立 3 セッション間の一致率

盲検では判定者が独立しているため、**本当の意味での実行間のばらつき**を測れます。

| 母集団 | 一致 | 一致率 |
|--------|------|--------|
| 3 体のいずれかが判定した全セル（和集合 64 セル） | 51 | **79.7%** |
| 3 体すべてが判定したセル（60 セル） | 51 | **85.0%** |
| **正解の違反にあたるセル（8 セル）** | 8 | **100%** |

不一致の内訳（13 セル）:

| ページ | 達成基準 | セッション1 | セッション2 | セッション3 |
|--------|---------|------------|------------|------------|
| 全 4 ページ | 1.3.2 | pass | **判定せず** | pass |
| 全 4 ページ | 1.4.13 | not-applicable | **warning** | not-applicable |
| 全 4 ページ | 2.2.2 | warning | warning | **not-applicable** |
| alpha-index | 1.4.5 | not-applicable | **pass** | not-applicable |

**不一致は 4 つの達成基準に集中しています**（うち 1.3.2 / 1.4.13 / 2.2.2 の 3 つは 4 ページ全てで同じ割れ方をし、1.4.5 は 1 ページのみ）。

- **1.3.2（意味のある順序）**: セッション2 だけが「判定できない」として判定を出さなかった
- **1.4.13（ホバー又はフォーカスで表示されるコンテンツ）**: 「該当コンテンツなし（not-applicable）」と「CSS を見ないと分からない（warning）」で割れた
- **2.2.2（一時停止・停止・非表示）**: 同上。CSS アニメーションの有無を HTML だけで断定してよいかで割れた

1.4.13 / 2.2.2 / 1.3.2 は **「該当なしと言い切ってよいか、未確認に倒すべきか」**の差、
1.4.5 は **「該当なし」と「合格」**という適合側どうしの表現の差です。
**違反を pass にしてしまう方向、あるいは違反を fail にし損なう方向の揺れは 0 件**でした。

そして **正解の違反にあたる 8 セルは 3 体が完全に一致しました。** 判定が割れるのは「違反がない箇所をどう表現するか」であり、
「違反があるかどうか」では割れていません。

### 4-8. 未確認率

| | warning 件数 / 判定した件数 | 未確認率 |
|---|---|---|
| セッション1 | 5 / 64 | 7.8% |
| セッション2 | 9 / 60 | 15.0% |
| セッション3 | 1 / 64 | 1.6% |

**この数字は「判定を試みた中で warning になった割合」であり、低いことが良いわけではありません。**
盲検の判定者は「判定できる項目だけを選んで判定した」ため、warning は少なくなります。
判定を出さなかった 39 〜 40 項目（55 − 15 〜 16）は、統合結果では機械検査由来の「未確認」として残ります。

ページ単位で見ると、統合後の「未確認」は alpha で 26 〜 30 件、beta で 23 〜 30 件です（[4-5](#4-5-ai-判定の貢献機械検査だけとの比較) の表）。
**55 項目の半分前後は、機械検査でも AI でも埋まらない**というのが実態です。

## 5. 発見事項

測定中に見つけた検査ロジックの気になる点です。**このレポートでは記録にとどめ、修正していません。**

1. **2.5.8（ターゲットサイズ）を「不適合」として出せる経路がない。**
   beta-index の 18×18px の SNS アイコン（NG-11）に対して、axe の `target-size` は隣接ターゲットがないため spacing exception で pass、
   Visual の `checkTargetSize` は warning、AI は実寸を測れないため判定対象にすらしませんでした。統合後も「未確認」のままです。

2. **Visual の `checkHeadingStructure` は beta-index の見出しスキップを検出しているのに、閾値のせいで「未確認」止まりになる。**
   このチェックは `result: issues.problems.length > 2 ? "fail" : "warning"`（`a11y-visual-test.ts`）で、
   **問題が 3 件以上のときだけ fail を返します**。beta-index の h1→h3 スキップは 1 件だったため warning になりました。
   今回は AI 判定が 1.3.1 を fail にしたため統合後は「不適合」になりましたが、AI 判定がなければ NG-06 は「未確認」で終わります。
   「見出しレベルの飛びが 1 件だけなら未確認」という閾値が妥当かは検討の余地があります。

3. **1.1.1（代替テキストの内容）と 2.4.2（ページタイトルの内容）が、どの経路でも埋まらない。**
   `alt="画像"`（NG-07）も `<title>ページ</title>`（NG-16）も、属性・要素は存在するため axe は発火しません。
   盲検の判定者 3 体は、いずれもこの 2 項目を判定対象に選びませんでした。
   **「存在はするが内容が不適切」という、生成 AI がもっとも力を発揮できるはずの領域が空いています。**
   SKILL.md ステップ5 が 1.1.1 / 2.4.2 を明示的に判定対象として挙げていないことが一因と考えられます。

4. **3.2.3（一貫したナビゲーション）はページ単位判定の構造上、検出できない。**
   `claude-overrides.json` がページ単位で、複数ページのツリーを突き合わせる入力経路が SKILL.md ステップ5 に定義されていません。

5. **証拠必須ガードは `evidence` の非空しか検査しない。**
   実在しない要素を引用した「幻覚した証拠」はガードを通過します。今回は幻覚 0 件でしたが、
   **逐語引用ではなく要約された引用（`<main id="main">` ↔ `<main id="main" class="content">`）は 20 件ありました**。
   ガードが守っているのは「証拠を書かせること」であって「証拠が正確であること」ではありません。

## 測定の限界

### 解消したもの

1 回目の測定にあった次の 2 点は、盲検プロトコルで解消しました。

- ~~判定した AI が事前に正解データを読んでいる~~ → **中立名リネーム + リポジトリアクセス禁止で解消**
- ~~同一セッション内の 3 回で独立していない~~ → **会話文脈を持たない独立エージェント 3 体で解消**

### 残っている限界

**この数字を引用するときは、以下を必ず併記してください。**

#### 1. 検査対象が自前のダミーサイト 1 構成 4 ページである

実サイトの多様性（SPA、CMS 出力、広告・埋め込み、大規模ページ、多言語）を代表しません。
ダミーサイトは素の HTML / CSS のみで JavaScript を一切含まないため、
判定者の not-applicable の多くが「script 要素なし」「audio/video なし」に依存しています。実サイトではこの割合は大きく変わります。

また、仕込んだ違反は「AI が検出できるか試す」意図で設計されたものです。実サイトの違反はもっと曖昧で、判別しにくい形で現れます。

#### 2. 判定者と検査対象の作成者が同系のモデルである

ダミーサイトと ground-truth.md を設計したのも、判定を行ったのも、同じ系列のモデルです。
「作った側が想定した壊し方」を「同じ系列のモデルが読み取る」構図であり、
人間が作った実サイトの欠陥に対して同じ成績が出る保証はありません。

#### 3. 2 つの変種が存在すること自体は判定者に見えている

`alpha` / `beta` の対応は伏せましたが、**同一レイアウトの 2 バージョンを判定させている**という構図自体は
判定者から観察可能です。「これは比較実験だ」と気づけば、差異を探す方向に注意が向く可能性があります。
1 バージョンだけを単独で提示する設計にはしていません。

#### 4. 「間違った合格 0 件」は仕込んだ違反についての 0 件である

ground-truth.md は ok 版が WCAG 2.2 A + AA に全面適合していることを保証していません。
保証しているのは「仕込んだ違反がないこと」です。したがって precision の分子に入っている 42 〜 54 件のうち、
独立に適合を検証したものは一部にすぎません。

#### 5. 判定対象の選択が判定者に委ねられている

盲検では「どの項目を判定するか」を判定者が決めています。このため
**「間違った合格 0 件」と「判定を試みなかった 13 件」はトレードオフの関係**にあります。
判定範囲を強制的に 55 項目へ広げれば、検出は増えるかもしれませんが、間違った合格も出うる、という関係です。
本測定はその条件での値を持っていません（1 回目の汚染測定では 55 項目すべてを判定させ、
検出 15 / 21・間違った合格 0 でしたが、正解を知っていたため比較には使えません）。

### 算出できなかった指標

- **偽陽性率（AI が誤って fail を出す率）の意味のある推定**: 今回は誤検出 0 件でしたが、正解データが「違反あり」の箇所しか列挙していないため、
  「正解が適合と保証している項目」の母数が確定しません。0 件という事実は記録できますが、率としての推定はできませんでした
- **実サイトでの精度**: 検査対象がダミーサイトのみのため測定していません
- **判定範囲を 55 項目に固定した場合の盲検精度**: 未実施

## まとめ

**測定できたこと。**

- 正解を知らない独立した 3 セッションで、**間違った合格 0 件・間違った不合格 0 件**
- 判定を試みた**正解の違反 8 件は 3 セッションとも全て検出**、正解の違反にあたるセルの**判定一致率は 100%**
- 生成 AI 判定は、機械検査だけでは「未確認」で終わる **5 件**の違反を追加で「不適合」にした（9 / 21 → 14 / 21）
- 証拠として引用した要素・属性は 173 判定すべてが実在した（ただし 20 件は逐語ではなく要約された引用）
- 一方で、**判定を試みたのは 55 項目中 15 〜 16 項目**にとどまり、正解の違反 21 件のうち **13 件は判定の対象にならなかった**
- 3 セッション間の不一致 15% は、すべて適合側の表現の差か「該当なし」と「未確認」の温度差であり、違反を見落とす方向の揺れは 0 件だった

**測定できていないこと。**

- 実サイトでの精度
- 判定範囲を 55 項目に固定した場合の盲検精度
- 証拠必須ガード・遷移制限の有効性（今回も作動条件が発生しなかった）
- 人間が作った欠陥に対する成績（検査対象と判定者が同系のモデル由来のため）
