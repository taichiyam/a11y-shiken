# 生成 AI 判定の精度実測レポート（2026-08-20）

このレポートは、a11y-shiken の **生成 AI（Claude）判定そのもの**（[SKILL.md](../skills/a11y-shiken/SKILL.md) ステップ5）が
どれくらい当たるのかを、正解データつきの検査対象で実測した記録です。

axe-core / Visual / Interactive の機械検査の精度は対象外です。機械検査は決定的で、
検出内容は [examples/site/ground-truth.md](../examples/site/ground-truth.md) に実測済みの結果があります。

**先に結論を書きます。**

| 指標 | 実測値 |
|------|--------|
| 間違った合格（正解が違反の項目に AI が pass / not-applicable を出した数） | **0 件 / 21**（生の AI 判定・統合後とも） |
| 間違った不合格（正解にない項目に AI が fail を出した数） | **0 件 / 220** |
| 検出（正解の違反を AI が fail にできた数） | **15 件 / 21**。逃した 6 件はすべて warning で、pass に倒れた例はなし |
| 未確認率（AI 判定対象のうち warning の割合） | **39.5 〜 40.5%**（220 項目中 87 〜 89 件） |
| 実行間のブレ（3 回で判定が変わったページ×項目） | **2 / 220 = 0.9%**。いずれも pass → warning 方向 |
| 証拠品質（evidence が実在の要素・属性を指しているか） | **幻覚 0 件 / 396 判定** |

そして、この数字を読むうえで外せない条件が 4 つあります。**[測定の限界](#測定の限界)を読まずにこの表だけを引用しないでください。**
特に「間違った合格 0 件」は、**判定した AI が事前に正解データを読んでいた**状態での値であり、上限に寄った見積もりです。

## 1. 何を測ったか

a11y-shiken の判定は 4 つの経路の合成です（詳細は [how-it-works.md](how-it-works.md)）。

1. axe-core（機械・決定的）
2. Visual テスト（Playwright・決定的）
3. Interactive テスト（Playwright・決定的）
4. **生成 AI（Claude）判定** ← 今回の測定対象
5. 統合スクリプト `generate-checklist-xlsx.ts`（証拠必須ガード・遷移制限を適用）

測ったのは 4 と、4 が 5 を通ったあとの結果です。

## 2. 測定プロトコル

### 判定対象の定義

**AI 判定対象 = 55 項目すべて**としました。

SKILL.md ステップ5 は「axe-core で未確認となった項目」を AI の分析対象と定めていますが、
55 項目の `axeCoverage` は現時点で全件 `partial` のため、axe-core が違反を出した項目以外はすべて未確認から始まります。
分母を実行ごとに揺らさないため、毎回 55 項目すべてに対して判定（pass / fail / not-applicable / warning）を出す運用に固定しました。

したがって 1 実行あたりの判定は **4 ページ × 55 項目 = 220 件**、3 実行で 660 件です。

### 手順

1. **機械検査を各ページ 1 回**（決定的なので 1 回）
   - `a11y-test.ts`（axe-core）/ `a11y-visual-test.ts` / `a11y-interactive-test.ts` / `a11y-tree.ts`
2. **AI 判定を各ページ 3 回**
   - 入力は `a11y-tree.txt` と、SKILL.md ステップ5 が「ツリーに現れないため HTML で判定する」と定める範囲の HTML 抽出のみ
     （`<head>` / `<img>` `<audio>` `<video>` `<iframe>` / `<a href>` / `lang` 属性 / `autocomplete` 属性 / `script` `accesskey` の有無）
   - 機械検査の結果 JSON は AI 判定の入力に **含めていません**（axe の答えを見てから判定すると測定にならないため）
   - 実行2・実行3 は、前の回の集計結果を見ないまま同じ入力から判定をやり直し、
     **前の回から判定が変わった項目だけを差分として記録**している（変わらなかった項目は前の回の判定と証拠をそのまま引き継いでいる）。
     前の回の出力そのものは同一セッションの文脈に残っているため、これは独立試行の近似にすぎない
     （→ [測定の限界 2](#2-同一セッション内の-3-回は完全に独立ではない)）
3. **各回について `generate-checklist-xlsx.ts` で統合**し、`merged-result.json` を得る
4. **ground-truth.md と突き合わせて集計**

比較の基準線として、`claude-overrides.json` を空（`{"overrides":[]}`）にした「AI 判定なし」の統合結果も 1 回作成しました。

### 再現手順

```bash
# 1. 検査対象をローカル配信
python3 -m http.server 8123 --directory examples/site

# 2. 機械検査（ページごとに実行。4 ページぶん繰り返す）
cd skills/a11y-shiken
bun scripts/a11y-test.ts             http://localhost:8123/ng/index.html > <dir>/axe-result.json
bun scripts/a11y-visual-test.ts      http://localhost:8123/ng/index.html > <dir>/visual-result.json
bun scripts/a11y-interactive-test.ts http://localhost:8123/ng/index.html --screenshot-dir <dir>/screenshots > <dir>/interactive-result.json
bun scripts/a11y-tree.ts             http://localhost:8123/ng/index.html --output <dir>/a11y-tree.txt

# 3. a11y-tree.txt と HTML 抽出だけを入力に claude-overrides.json を書く（SKILL.md ステップ5）
# 4. マニフェストを書いて統合
bun scripts/generate-checklist-xlsx.ts --manifest <dir>/manifest.json --output <dir>/checklist.xlsx
```

集計の元データ（各回の `claude-overrides.json` / `merged-result.json`）はリポジトリに含めていません。
上の手順で再生成できます。集計スクリプトが行っている突き合わせは、本レポートの表としてすべて転記しています。

## 4. 結果

### 4-1. 間違った合格（最重要）

**正解が違反とする 21 項目に対し、AI が pass / not-applicable を出した数。**

| | 生の `claude-overrides.json` | 統合後 `merged-result.json` |
|---|---|---|
| 実行1 | 0 / 21 | 0 / 21 |
| 実行2 | 0 / 21 | 0 / 21 |
| 実行3 | 0 / 21 | 0 / 21 |

**生の判定の時点で 0 件でした。** つまり今回の測定では、証拠必須ガード・遷移制限が止めるべき「間違った合格」が
そもそも 1 件も発生していません。

### 4-2. ガードが実際に止めた件数

| ガード | 実装 | 今回の作動件数 |
|--------|------|----------------|
| 証拠必須ガード（`evidence` 空の pass / fail / not-applicable を warning へ降格） | `sanitizeClaudeOverrides()` | **0 件**（3 実行合計 396 件の pass / fail / not-applicable すべてに evidence があったため） |
| 遷移制限（証拠のない「適合」への上書きを却下） | `applyOverrideStatus()` | **0 件**（AI が「不適合」を「適合」で覆そうとした試行が 0 件） |
| 判定矛盾フラグ `conflict: true` | 同上 | **0 件** |

**ガードは「今回は何も止めなかった」というのが実測結果です。** 有効性を否定するものではありませんが、
本測定は **ガードの効果を実証していません**。効果を確かめるには、証拠なしの判定や不適合の覆しが実際に発生する条件が必要です。

なお証拠必須ガードは `evidence` が**空文字でないこと**しか検査しません。
存在しない要素を引用した「幻覚した証拠」はこのガードを素通りします（今回の実測では幻覚 0 件だったため実害は出ていません → [4-6](#4-6-証拠品質)）。

### 4-3. precision（AI が「合格」と言った判定の正しさ）

分母は AI が pass または not-applicable を出した判定の総数、分子はそのうち正解データが違反としていないものです。

| | pass | not-applicable | 合計（分母） | 間違った合格 | precision |
|---|---|---|---|---|---|
| 実行1 | 43 | 72 | 115 | 0 | **1.000** |
| 実行2 | 42 | 72 | 114 | 0 | **1.000** |
| 実行3 | 41 | 72 | 113 | 0 | **1.000** |

**この 1.000 は「仕込んだ違反を合格にしなかった」という意味であって、「ok 版の 55 項目すべてが WCAG に適合していると確認できた」という意味ではありません。**
ground-truth.md が保証しているのは「仕込んだ違反の不在」であって、ok 版の全項目適合ではありません。
分子に入っている 113 〜 115 件の大半は「正解データが違反として挙げていない」だけで、独立に適合を検証したものではありません。

### 4-4. 検出（正解の違反を fail にできたか）

| ページ | 正解の違反 | AI が fail | AI が warning（逃した） | AI が pass（事故） |
|--------|-----------|-----------|------------------------|-------------------|
| ng-index | 10 | 7 | 3（1.4.3 / 2.4.7 / 2.5.8） | 0 |
| ng-contact | 11 | 8 | 3（1.4.11 / 2.4.7 / 3.2.3） | 0 |
| **合計** | **21** | **15（71.4%）** | **6（28.6%）** | **0** |

3 実行とも同じ値でした。

**逃した 6 件はすべて warning です。** 設計どおりの安全側の動作であり、「確認OK」として利用者に見せてしまう事故は起きていません。
逃した理由も入力の性質から説明がつきます。

| 逃した基準 | 理由 |
|-----------|------|
| 1.4.3（コントラスト） | 色の計算に CSS が必要。アクセシビリティツリー・HTML 抽出には含まれない |
| 1.4.11（非テキストのコントラスト） | 同上 |
| 2.4.7（フォーカスの可視化） | `:focus` の CSS が必要 |
| 2.5.8（ターゲットサイズ） | 実寸のレイアウト計測が必要 |
| 3.2.3（一貫したナビゲーション） | 複数ページの比較が必要。`claude-overrides.json` はページ単位のため構造的に判定できない |

このうち 1.4.3 は axe-core、1.4.11 は Visual、2.4.7 は Interactive が検出しています。
**AI が苦手な領域と、機械検査が得意な領域はきれいに分かれていました。**

### 4-6. 証拠品質

3 実行で出た pass / fail / not-applicable の判定 **396 件**すべてについて、`evidence` の記述が
実際のアクセシビリティツリー / HTML と一致するかを照合しました。

`evidence` の主張を 2 種類に分けて検証しています。

| 種類 | 検証方法 | 件数 | 結果 |
|------|---------|------|------|
| 肯定的引用（「この要素・属性が存在する」） | 引用文字列がツリー / HTML に実在するか機械照合 | 141 判定 | **実在 141 / 実在しない 0** |
| 否定的主張（「この要素が存在しない」） | 主張された不在が実際に成り立つかをページから算出した事実表と照合 | 273 判定 | **主張どおり 273 / 誤り 0** |
| 定性的主張（読み上げ順・感覚的特徴の不在など） | 目視レビュー | 39 判定（重複を除くと 13 種） | **13 種すべて確認、誤りなし** |

（1 つの判定が肯定的引用と否定的主張の両方を含む場合があるため、上 2 行は重複を含みます。どちらの自動照合にもかからなかった判定が 39 件です）

**存在しない要素・属性を引用した「幻覚した証拠」は 0 件でした。**

引用の例:

- `- img "画像"` → ng-index のツリーに実在（1.1.1 fail の根拠）
- `- button "フォーム": 送信する` → ng-contact のツリーに実在（2.5.3 fail の根拠）
- `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no">` → ng-contact の HTML に実在（1.4.4 fail の根拠）
- 「HTML に script 要素0件」→ 4 ページとも実際に 0 件

### 4-7. 実行間のブレ

ページ×項目 = 220 セルのうち、3 回の間で判定が変わったもの。

| ページ | 達成基準 | 実行1 | 実行2 | 実行3 | 統合後の変化 |
|--------|---------|-------|-------|-------|-------------|
| ok-index | 1.4.5（文字画像） | pass | warning | warning | 適合 → 未確認 |
| ng-contact | 2.4.4（リンクの目的） | pass | pass | warning | 適合 → 未確認 |

**ブレた項目: 2 / 220 = 0.9%**（生の判定・統合後とも同じ 2 件）。

内訳:

- ok-index 1.4.5: 画像が SVG であり、代替テキストは情景を説明しているものの、SVG 内に文字が描かれていないことを入力から確認できない。1 回目は pass、2 回目以降は warning
- ng-contact 2.4.4: ナビゲーションのリンクテキスト「ご案内」が単独で行き先（`facility.html`）を説明できているか断定しづらい。3 回目に warning へ

**2 件とも pass → warning の一方向で、時間が進むほど warning に寄っています。** これはランダムな揺れではなく、
同一セッション内で判断が収束していく方向のドリフトです。**独立でない 3 回だからこそ出た形であり、
この 0.9% を「実行ごとのばらつき」として一般化することはできません**（→ [測定の限界](#測定の限界)）。

**逆方向（warning → pass、pass → fail）のブレは 0 件でした。** 危険な方向へ揺れた例はありません。

### 4-8. 未確認率

| | warning 件数 / 220 | 未確認率 |
|---|---|---|
| 実行1 | 87 | 39.5% |
| 実行2 | 88 | 40.0% |
| 実行3 | 89 | 40.5% |

**AI 判定の 4 割は「未確認」です。** アクセシビリティツリーと限定的な HTML 抽出だけでは、
CSS の算出値（コントラスト・フォーカスリング・実寸）、実際の操作（Tab 移動・フォーム送信）、
複数ページの比較を要する基準に踏み込めないためです。これは入力の設計上の帰結であり、判定能力の不足とは別の話です。

## 5. 発見事項

測定中に見つけた検査ロジックの気になる点です。**このレポートでは記録にとどめ、修正していません。**

1. **2.5.8（ターゲットサイズ）を「不適合」として出せる経路がない。**
   ng-index の 18×18px の SNS アイコン（NG-11）に対して、axe の `target-size` は隣接ターゲットがないため spacing exception で pass、
   Visual の `checkTargetSize` は warning、AI はツリーから実寸を測れず warning。3 経路すべてが warning に倒れ、統合後も「未確認」のままです。

2. **Visual の `checkHeadingStructure` は ng-index の見出しスキップを実際に検出しているが、設計上 warning 固定のため統合結果に反映されない。**
   出力は `1件の見出し構造の問題を検出（6個の見出し要素）` と具体的です。今回は AI 判定が 1.3.1 を fail にしたため統合後は「不適合」になりましたが、
   AI 判定がなければ NG-06 は「未確認」で終わります（[4-5](#4-5-ai-判定の貢献機械検査だけとの比較) の比較表）。

3. **3.2.3（一貫したナビゲーション）は生成 AI 判定の構造上、検出できない。**
   `claude-overrides.json` がページ単位で、複数ページのツリーを突き合わせる入力経路が SKILL.md ステップ5 に定義されていません。
   NG-04 はナビゲーションのラベル・並び順の差異という明確な違反ですが、今回 3 実行とも warning でした。

4. **証拠必須ガードは `evidence` の非空しか検査しない。**
   実在しない要素を引用した「幻覚した証拠」はガードを通過します。今回は幻覚 0 件だったため実害はありませんでしたが、
   ガードが守っているのは「証拠を書かせること」であって「証拠が正しいこと」ではありません。

## 測定の限界

**この数字を引用するときは、以下 4 点を必ず併記してください。**

### 1. 判定した AI が、事前に正解データを読んでいる

本測定では、判定者と測定者が同一セッションであり、その AI は判定の前に
[ground-truth.md](../examples/site/ground-truth.md)（どこに何を仕込んだかの一覧）を読んでいます。

- **「検出 15 / 21」は上限に寄った見積もり**です
- **「間違った合格 0 件」は下限に寄った見積もり**です。正解を知らない状態なら、より多く出た可能性があります

正解データを読まない実行環境で判定させる盲検プロトコルは、本測定では実施していません。今後の課題です。

### 2. 同一セッション内の 3 回は完全に独立ではない

前の回の判定の記憶を排除しきれません。加えて実行2・3 は、再判定の結果を前の回からの**差分として記録**する手順を取っています
（[2 章](#手順)）。判定そのものはやり直していますが、変化がなかった項目は前の回の出力をそのまま引き継ぐため、
「毎回ゼロから書き起こしたら同じになったか」までは検証できていません。実測したブレ 0.9% は **下限の見積もり**です。
実際、ブレた 2 件はどちらも「回を重ねるほど warning へ寄る」一方向のドリフトで、
独立試行のランダムなばらつきとは性質が異なります。別セッション・別プロセスで実行すればブレはこれより大きくなると考えるべきです。

### 3. 検査対象が自前のダミーサイト 2 構成 4 ページである

実サイトの多様性（SPA、CMS 出力、広告・埋め込み、大規模ページ、多言語）を代表しません。
ダミーサイトは素の HTML / CSS のみで JavaScript を一切含まないため、
1 実行あたり 72 件ある not-applicable のうち 28 件は「HTML に `script` 要素0件」を根拠にしたものです
（2.1.4 / 2.2.1 / 2.3.1 / 2.5.1 / 2.5.2 / 2.5.4 / 2.5.7 × 4 ページ）。JavaScript を使う実サイトでは、この 28 件は該当ありに変わり、
静的解析だけでは判定できない warning へ移る可能性が高いと考えられます。

また、仕込んだ違反は「AI が検出できるか試す」意図で設計されたものです。実サイトの違反はもっと曖昧で、判別しにくい形で現れます。

### 4. 「間違った合格 0 件」は仕込んだ違反についての 0 件である

ground-truth.md は ok 版が WCAG 2.2 A + AA に全面適合していることを保証していません。
保証しているのは「仕込んだ違反がないこと」です。したがって precision の分子に入っている 113 〜 115 件のうち、
独立に適合を検証したものは一部にすぎません。

### 算出できなかった指標

- **偽陽性率（AI が誤って fail を出す率）の意味のある推定**: 今回は誤検出 0 件でしたが、正解データが「違反あり」の箇所しか列挙していないため、
  「正解が適合と保証している項目」の母数が確定しません。0 件という事実は記録できますが、率としての推定はできませんでした
- **実サイトでの精度**: 検査対象がダミーサイトのみのため測定していません

## まとめ

**測定できたこと。**

- 生成 AI 判定は、機械検査だけでは「未確認」で終わる 10 件の違反を追加で「不適合」にした（9 / 21 → 19 / 21）
- 正解の違反を「確認OK」にしてしまう事故は 0 件だった
- 逃した 6 件はすべて warning に倒れ、危険側には倒れなかった
- 証拠として引用した要素・属性は 396 判定すべてが実在した
- 判定の 4 割は「未確認」で、これは入力（アクセシビリティツリー + 限定 HTML）の設計上の帰結

**測定できていないこと。**

- 正解を知らない状態での精度（盲検）
- 独立した実行間の再現性
- 実サイトでの精度
- 証拠必須ガード・遷移制限の有効性（今回は作動条件が発生しなかった）
