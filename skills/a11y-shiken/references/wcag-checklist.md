# WCAG 2.2 Level A + AA チェックリスト

自動検査（axe-core / Visual テスト / Interactive テスト）が **pass または fail を出せるか** で3カテゴリに分類。

- 🤖 **自動チェック**: 自動検査が pass/fail を出し、達成基準の要求をほぼ満たして検証する。pass はそのまま「確認OK」になる（**1.4.3 のみ**）
- 🔄 **部分自動チェック**: 自動検査が pass/fail を出すが、**達成基準の一部しか見ていない**。残りは目視確認が必要
- 👁 **目視確認**: 対象コンテンツがあるとき、自動検査が pass/fail を出さない（「該当コンテンツなし」の pass を除き、常に「未確認」になる）。生成AI判定か人の確認が必要

> ⚠️ **axe-core の pass だけでは「確認OK」になりません（1.4.3 を除く）。**
> 55項目の定義は `axeCoverage`（`full` / `partial`）フラグを持ち、**達成基準の一部しか検証していない
> `partial` の項目では、axe-core の `passes` に一致しても「未確認」に倒す**。備考には
> 「axe-core は達成基準の一部のみ検証（{ルール名}）。この pass だけでは適合と判定していません」が入る。
> `full` は 1.4.3（`color-contrast` がコントラスト比そのものを計測する）だけで、残る54項目は `partial`。
>
> このガードが変えるのは pass の扱いだけで、**`violations` による「修正あり」・`incomplete` による「未確認」は
> 従来どおり**。また Visual / Interactive / 生成AI が **証拠つきで pass を出した場合は従来どおり「確認OK」** になる。
>
> ⚠️ **🔄 の項目は「確認OK」でも安心材料になりません。**
> 検査した範囲でしか合格を意味しません。各行の確認ポイントに「何を見ているか」を明記しているので、
> 表示された結果を額面どおり受け取る前に必ず確認すること。
>
> 判定の全体像は `docs/how-it-works.md`（https://github.com/taichiyam/a11y-shiken ）の第2章・第3章を参照。

> axe-core のルール名は **axe-core 4.11.1** で実際に実行して確認したもの。
> 検査は WCAG タグ（wcag2a / wcag2aa / wcag21a / wcag21aa / wcag22a / wcag22aa）のみで実行するため、
> `region` / `landmark-one-main` / `heading-order` / `empty-heading` 等の best-practice ルールは発火しない。
> また、axe-core はタグ指定実行のとき既定で `experimental` / `deprecated` タグを持つルールを除外する
> （`tagExclude`）。このため WCAG タグを持っていても **`audio-caption`（1.2.1、deprecated）と
> `css-orientation-lock`（1.3.4、experimental）は実行されない**（結果の inapplicable にも現れない）。
> この2基準に axe-core の検査は効いていない。
> なお `enabled: false` 自体は実行されない理由にならない（例: `target-size` は `enabled: false` だが
> 両タグを持たないため実行される。実測では `passes` に現れた）。

| 1.4.1 色の使用 | A | 🔄 部分自動 | axe-core の `link-in-text-block`（本文中のリンクが色以外でも識別できるか）のみを検出。**エラー表示・グラフ・アイコンなど、色だけで情報を伝えている箇所全般は検証していない**（目視確認が必要） |

| 1.4.3 コントラスト（最低限） | AA | 🤖 自動チェック | axe-core の `color-contrast` でテキストと背景のコントラスト比が4.5:1以上（大文字テキストは3:1以上）かを計算。背景画像・グラデーション上のテキストは incomplete（要確認）に倒れる。**達成基準の要求そのものを計測する唯一の項目で、`axeCoverage` が `full` なのはこの1項目だけ** |

| 1.4.5 文字画像 | AA | 👁 目視確認 | テキストの代わりに画像化された文字を使用していないか（ロゴ等の例外を除く）。**対応する自動検査は存在しない** |
| 1.4.10 リフロー | AA | 🔄 部分自動 | Interactive テストがビューポートを320x256pxに変更し、`documentElement.scrollWidth > clientWidth` で横スクロールの発生を判定（pass/fail あり）。横スクロールは出ないがコンテンツが読めない・重なっている場合は検出できない |
| 1.4.11 非テキストのコントラスト | AA | 🔄 部分自動 | Visual テストが `button` / `input` / `select` / `textarea` / `[role=button]` の**境界線と背景**のコントラスト比のみを計算。アイコン・グラフィック・状態表示・境界線のないコンポーネントは検証できないため、**問題未検出でも pass は出さず warning** |
| 1.4.12 テキストの間隔 | AA | 🔄 部分自動 | axe-core の `avoid-inline-spacing`（インラインスタイルで行間等を `!important` 固定していないか）のみを検出。**実際に行の高さ1.5倍・段落間隔2倍・文字間隔0.12倍・単語間隔0.16倍へ変更したときの表示崩れは検証していない** |
| 1.4.13 ホバー又はフォーカスで表示されるコンテンツ | AA | 👁 目視確認 | ホバー/フォーカスで表示されるコンテンツ（ツールチップ等）が、解除可能・ホバー維持可能・自動非表示しないか。**対応する自動検査は存在しない** |

| 3.2.1 フォーカス時 | A | 🔄 部分自動 | Interactive テストが最大10要素でフォーカス前後のURL・DOMスナップショットを比較し、メインフレームのナビゲーションも監視（同一URLへの reload / replace を含む遷移は fail、DOM変化は warning、変化なしを確認できた場合のみ pass）。**11要素目以降と、DOM変化が実害のあるコンテキスト変化かどうかの意味的判断は行わない** |
| 3.2.2 入力時 | A | 🔄 部分自動 | Interactive テストが最大5フィールド（テキスト系 input 全種・number・textarea・select・checkbox / radio）の値を変更し、前後のURL・DOMスナップショット比較 + ナビゲーション監視で判定（遷移は fail、DOM変化は warning、変化なしを確認できた場合のみ pass。`date` / `range` / `file` 等の未対応タイプが残る場合は warning）。**フォーム送信後の挙動は検証していない** |

| 3.2.4 一貫した識別性 | AA | 👁 目視確認 | 同じ機能を持つコンポーネントが一貫して識別されているか（同じアイコン、ラベルを使用）。**ページ間比較が必要なため自動判定できない** |
| 3.2.6 一貫したヘルプ | A | 👁 目視確認 | ヘルプ手段（連絡先、チャットbot等）が複数ページ間で一貫した相対的な位置にあるか。**ページ間比較が必要なため自動判定できない** |

### 3.3 入力支援

| 達成基準 | レベル | チェック種別 | 確認ポイント |
|---------|--------|------------|-------------|
| 3.3.1 エラーの特定 | A | 👁 目視確認 | 入力エラーが自動検出された場合、エラー箇所と内容がテキストで説明されているか。Visual テストは**フォーム要素の有無しか見ず**、フォームが無ければ「該当コンテンツなし」で pass、有れば必ず warning を返す（fail は返さない）。**フォーム送信もバリデーション発火も行わないため、エラー表示の実在は検証していない** |
| 3.3.2 ラベル又は説明 | A | 🔄 部分自動 | axe-core の `form-field-multiple-labels`（ラベルが重複していないか）のみが pass/fail を出す。**ラベルの存在・説明の適切さを見ていないため `partial` 扱いで、pass しても「未確認」のままになる**。**ラベルの紐付けを見る axe-core の `label` ルールは `wcag412` タグのため 4.1.2 側に集計される**。Visual テストはフォーム要素の有無しか見ない。説明の適切さは目視確認 |
| 3.3.3 エラー修正の提案 | AA | 👁 目視確認 | 入力エラーが検出された場合、修正方法の提案が提示されるか。Visual テストは**フォーム要素の有無しか見ず**、フォームが有れば必ず warning。**修正提案の実在は検証していない** |
| 3.3.4 エラー回避（法的、金融、データ） | AA | 👁 目視確認 | 法的/金融的な取引やデータ送信の前に、確認・修正・取消が可能か。**対応する自動検査は存在しない** |
| 3.3.7 冗長な入力 | A | 👁 目視確認 | 同一プロセス内で以前に入力された情報の再入力を求めないか（自動入力、選択肢からの選択等の手段があるか）。Visual テストは**フォーム要素の有無しか見ず**、フォームが有れば必ず warning。**複数ステップの追跡は行っていない** |
| 3.3.8 アクセシブル認証（最小） | AA | 👁 目視確認 | 認証プロセスが認知機能テスト（パスワード記憶、パズル解読等）のみに依存していないか。Visual テストは **`input[type="password"]` の有無しか見ず**、無ければ「該当コンテンツなし」で pass、有れば必ず warning |

## 4. 堅牢 (Robust)

### 4.1 互換性

| 達成基準 | レベル | チェック種別 | 確認ポイント |
|---------|--------|------------|-------------|
| 4.1.2 名前（name）、役割（role）及び値（value） | A | 🔄 部分自動 | axe-core の28ルール（`button-name` / `label` / `link-name` / `select-name` / `input-button-name` / `aria-*` 系等）で role・name・ARIA 属性の妥当性を検出。**カスタムコンポーネントの状態（value）が操作に応じて正しく更新されるかは検証していない** |
| 4.1.3 ステータスメッセージ | AA | 👁 目視確認 | axe-core に `wcag413` タグを持つルールは存在しない（axe-core 4.11.1 で確認）。Visual テストが `aria-live` 領域・`role="status"`/`"alert"`/`"log"` の有無を列挙し、動的コンテンツと思われるクラス名（`.notification` / `.toast` 等）で未設定のものも列挙する。**属性の存在検査だけでは達成基準を検証できないため、pass も fail も返さず常に warning**。メッセージが実際に支援技術へ伝わるかは目視確認 |
